# Challenge 4: Deploy Windows 365 Flex Shared Desktop or Cloud Apps

[Previous Challenge](./03-W365-App-Deployment.md) - **[Home](../../README.md)**

## Introduction

**Windows 365 Flex in Shared mode** lets a group of users share a Cloud PC at different times. One license provides **one shared Cloud PC with one concurrent user session**.

Users can access either a **full Cloud PC desktop** or individual **Windows 365 Cloud Apps** running on the shared Cloud PC. Both options use **Shared mode**, not Flex Dedicated mode.

User data is removed from the shared Cloud PC after sign-out. **User Experience Sync** preserves supported user settings and application data in Microsoft-managed cloud storage for later sessions. Although optional in the product, we recommend enabling it and will use it in this challenge so users retain their personal settings.

## Challenge

Each participant has **one Windows 365 Flex license** available. Choose **one** option below and create a new provisioning policy in the **Microsoft Intune admin center**.

### 1. Configure the provisioning policy

Use these settings for either option. Replace `[n]` with your team number.

| Setting | Required value |
|---|---|
| Policy name | `PP-P[n]-Flex-YourPolicyName` |
| License type | **Windows 365 Flex** |
| Flex type | **Shared** |
| Join type | **Microsoft Entra join** |
| Network | **Microsoft-hosted network** |
| Region | **North Europe** |
| Image | A **Windows 11 gallery image** with the applications you want to test |
| Assignment | `GRP-P[n]-Users` |
| Cloud PC size | A size available with your lab's Flex license |
| Number of Cloud PCs | **1** |
| User Experience Sync | **Enabled** |

During policy creation, select **Enable user experience sync** in the configuration section and choose an available user storage size.

> **Important:** Use your own team number in the custom device name template, for example `CPC-P1-%RAND:5%` for team 1. The resulting name must be **5-15 characters long** and include a random component of **at least five characters**.

### 2. Configure and test your chosen experience

#### Option 1 - Shared full desktop

- Select **Access a full Cloud PC desktop** as the provisioning policy experience.
- Wait until the shared Cloud PC reports **Provisioned**.
- Connect through **Windows App** as a user in your assigned team group.
- Sign out completely to release the Cloud PC, then test access with another team user.

#### Option 2 - Cloud Apps

- Select **Access only apps which run on a Cloud PC** as the provisioning policy experience.
- Review the applications available in the selected image.
- After provisioning, open **All Cloud Apps** and publish discovered applications, for example **Word and Notepad**, if available.
- Wait until the apps report **Published**, then refresh **Windows App** and launch a published app as a team user.
- Sign out of the Cloud App session when finished to release the shared Cloud PC.

### 3. Verify that user settings persist

- Change a supported Windows setting or application preference in your chosen experience.
- Sign out completely, then reconnect as the **same user** and verify that the setting is retained.

## Pro Tips

> **1. Sign out, not just disconnect.** Only one user can use your shared Cloud PC at a time. End the session before testing with another user.

> **2. Enable User Experience Sync from the start.** This preserves each user's supported settings between sessions. Changing this option after provisioning requires deprovisioning and recreating the shared Cloud PCs, so configure it during policy creation.

## Success Criteria

- One **Shared-mode Cloud PC** is provisioned and assigned to your team group.
- Team users can access the chosen experience: a **full desktop** or **published Cloud Apps**.
- The session is released after sign-out so another assigned user can connect.
- **User Experience Sync** is enabled, and a user's supported setting or application preference persists after sign-out and reconnection.
